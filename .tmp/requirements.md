# フクナビ 要件定義書

---

# 1. アプリ概要

## アプリ名

フクナビ

## コンセプト

洋服好き・子ども服を探している人・プレゼント用の服を探している人向けに、
店舗と取り扱いブランドを比較しながら「行きたいお店」が見つかる服屋検索サービス。

## 目的

- 情報が少ないセレクトショップ等を可視化
- ブランドと店舗の紐付けを明確化
- ユーザーの「欲しい」情報を活用し、レコメンドと店舗価値を向上

---

# 2. 想定ユーザー

## 一般ユーザー（role: user）

- 洋服好き
- 子ども服を探す親
- プレゼント用途の利用者

## 店舗管理者（role: shop_owner）

- 自店舗情報を管理したい事業者
- 需要データを参考にしたい店舗

## 運営者（role: admin）

- データ管理・審査・モデレーション担当

# 3. 認証仕様

## 認証方式

- Googleログイン
- メール＋パスワードログイン
- 両方式は同一アカウントに統合可能
- 認証後は roleに応じてリダイレクト先を変えるだけ。

## アカウント一意性

- email を一意キーとする

## アカウント統合ルール

- メール登録済 → Googleログイン時に自動リンクせず、ユーザーに確認ステップを表示
  1. 「同じメールアドレスのアカウントが存在します」と通知
  2. 既存パスワード or メールOTPで本人確認
  3. 確認完了後にアカウントをリンク
- Google登録済 → メール設定時に既存へリンク（パスワード設定フローで完結）
- 二重アカウント禁止

## ログイン必須範囲

- レビュー投稿
- お気に入り登録
- ウィッシュ登録
- マイページ閲覧

閲覧（一覧・詳細・検索）は未ログイン可

## セキュリティ

- パスワードリセット
- メール変更時確認
- 重要操作時再認証

# 5. 一般ユーザー機能

## 店舗一覧

- フィルタ（エリア / カテゴリ / 価格帯 / タグ / ブランド）
- フリーワード検索
- ソート（人気順・新着順・高評価順）
- ページング

### カテゴリマスタ

- 内部コード：`mens` / `ladies` / `kids` / `unisex` / `vintage`
- 表示名：`メンズ` / `レディース` / `キッズ` / `ユニセックス` / `ヴィンテージ`
- 店舗カテゴリとウィッシュカテゴリは同一マスタを利用する

## 検索仕様

- 対象：店舗名 / ブランド名 / タグ / 市区町村
- 部分一致・AND検索
- 実装：PostgreSQL `tsvector` + `pg_bigm` 拡張による全文検索
  - 店舗名・ブランド名・タグを横断検索
  - GINインデックスで高速化
  - 一致度スコアによるランキングソート対応
- 同義語対応はリリース後フェーズで検討

## 店舗詳細

- 基本情報
- 取り扱いブランド
- レビュー一覧
- お気に入り登録

## レビュー

- 1ユーザー1店舗1レビュー
- 編集可
- 画像添付可
- 即時公開
- 通報ボタンあり（理由選択式）
  - 理由：虚偽情報 / 誹謗中傷 / 関係のない内容 / その他
  - 通報後は運営が確認し、必要に応じて非公開に変更
  - 通報されたレビューは `status: flagged` としてadminが管理画面で確認可能

### NGワード対策

- 自動フィルタ
- スコア型フラグ判定
  ※ レート制限なし

## ブランド登録

- ログインユーザーが新規ブランドを投稿可能
- 投稿時に既存ブランドの類似検索結果を表示（重複登録を抑制）
  - 入力中にリアルタイムで候補表示
  - 候補に一致するものがあれば選択を促す
- 正規名・読み仮名・別表記フィールドを持つ
- 投稿後は即時公開 + 運営通知

## ウィッシュ機能

### 登録項目

- タイプ（ブランド / アイテム / 条件）
- カテゴリ（必須）
- 価格帯（必須）
- エリア（必須）
- 任意：サイズ、タグ、新品/古着、緊急度、自由入力
- 公開/非公開選択
- 通知ON/OFF（通知手段：メール）

### 登録直後レコメンド

- カテゴリ・価格帯・エリアの完全一致で店舗を絞り込んで上位表示
- 一致した条件を理由として表示（例：「キッズ対応 / 渋谷エリア / ～5,000円」）
- スコアリング・機械学習によるランキングはリリース後フェーズで対応

# 6. 店舗管理者機能（有料会員限定）

## プラン対象

- role: shop_owner
- 有料会員のみ利用可能

## 提供機能

- 店舗管理へのログイン
- ダッシュボード（自店舗関連ウィッシュ需要）
- 店舗情報編集
  - 店舗名（変更時は運営承認）
  - 営業時間 / 定休日 / 電話 / URL / SNS / 説明文 / 写真
  - エリア分類
  - 価格帯分類

- 取り扱いブランド管理
- レビュー閲覧（返信不可）

## 編集不可

- 公開/非公開
- 店舗削除

# 10. データ取得方針

- 店舗データの新規登録は運営者（role: admin）のみ実行可能
- 未登録店舗の掲載申請はログインユーザー / 店舗オーナー候補から受付可能（Section 13 参照）
- ブランドデータはログインユーザーからの投稿を受け付け、即時公開＋運営通知
- レビューは投稿後即時公開
- 運営はブランド投稿・レビュー・通報を事後確認

---

# 11. 利用規約骨子

- 投稿著作権は投稿者に帰属
- フクナビは非独占的利用ライセンスを取得
- 権利侵害時削除対応
- 禁止事項明記（誹謗中傷、虚偽、営業妨害、自作自演等）

# 12. 店舗オーナー登録フロー

1. 申請フォーム送信
2. 店舗情報提出
3. 運営確認
4. 承認後 role付与＋店舗紐付け

---

# 13. 店舗掲載申請フロー

未登録店舗をユーザーまたは店舗オーナー候補が申請できる。

## 申請者

- ログイン済みの一般ユーザー（「この店舗を掲載してほしい」）
- 店舗オーナー候補（自店舗の掲載＋オーナー申請を同時に行う）

## フロー

1. 申請フォームから店舗情報を入力（店舗名・住所・カテゴリ・URL等）
2. 申請内容が運営に通知される
3. 運営が情報を確認・補完して店舗データを登録
4. 申請者にメール通知（掲載完了 or 却下）
5. オーナー申請を同時に行った場合は Section 12 フローへ移行

## 留意点

- 申請はあくまで「依頼」であり、掲載可否は運営判断
- 重複申請のチェックは申請フォームで既存店舗の類似検索を表示して抑制
